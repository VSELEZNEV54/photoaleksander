# ANPhotoLab — сайт фотографа Александра Непомнящих (v2 «Проявочная»)

Статический многостраничный сайт без бэкенда: только HTML, CSS и немного JavaScript (без библиотек).
v2 — редизайн по правкам заказчика: тёмная тема, только гротески, огромная типографика, умеренная анимация,
минимум текста (фотографа оценивают глазами). Бриф v2 — `_work/brief-v2.md`, код v1 сохранён в `_work/_backup_v1/`.
v3 — «тот же стиль, только аккуратнее» (`_work/brief-v3.md`): меньше элементов и больше воздуха — шапки секций без рамок
и мета-подписей, заголовки одного веса и меньше, сдержанные направления (наведение — лёгкое увеличение), без подписей
на плитках, бегущей строки и «стопки» кейсов, на «Контактах» — портрет Александра. Портфолио жанров — **альбомами съёмок**
(«Иван и Анна», «Алёна и Дима»…): на странице жанра сетка карточек, у каждого альбома своя страница `/<жанр>/<альбом>/`.
Готовый сайт — папка `site/`. Она открывается двойным кликом по `site/index.html` (без сервера)
и так же работает на любом статическом хостинге.

`build.py` — инструмент разработчика: собирает `site/` из контента. На хостинге его нет и он не нужен.

```
САНЯ/

  tools/photos.py        локальные AVIF/WebP для LCP-кадров (портрет, обложки) — нужен Pillow или macOS sips
  tools/add_album.py     добавить реальный альбом съёмки из папки с фото (уменьшает фото, пишет content/albums.json)
  src/
    config.json          домен, контакты, жанры, карта сайта (22 адреса), навигация в скобках, меню, подвал
    assets/css/main.css  вся дизайн-система: токены, каркас, блоки, моушн
    assets/js/main.js    подгонка огромных слов, лоадер и шторка переходов, появления, шапка, меню-оверлей,
                         вкладки, счётчики, бегущая строка (если стоит), вопросы, «Подробнее», лайтбокс, «наверх»
                         (форм нет — все CTA ведут в Telegram; направления и кейсы — на чистом CSS)
    assets/img/photos/   AVIF/WebP от tools/photos.py (если есть — сборка ставит <picture> сама)
    assets/img/albums/   кадры реальных альбомов: <жанр>/<slug>/01.jpg (2400 px) + 01-800.jpg (превью) — от tools/add_album.py
    assets/img/          favicon.svg, apple-touch-icon.png (рисуется сборкой, если файла нет)
  content/
    photos.json          манифест фото (id, жанр, ориентация, alt, три размера)
    albums.json          альбомы съёмок по жанрам (пока демо из photos.json) → сетка на жанре и страницы /<жанр>/<альбом>/
    reviews.json         16 отзывов дословно
    pages/*.json         одна страница = один файл
    BLOCKS.md            библиотека блоков v2: поля, примеры, объём текста, рецепты страниц
    TODO-facts.md        список цифр-заглушек и кейсов, которые нужно подтвердить у Александра
  site/                  СОБРАННЫЙ сайт — не редактировать руками, перезаписывается сборкой
  _work/                 рабочие материалы (бриф, SEO-план, прототипы) — на хостинг не выкладывать
```

## Сборка

```bash
python3 build.py                                  # полная сборка: site/ очищается и собирается заново
python3 build.py --check content/pages/x.json     # проверить страницу, ничего не записывая
python3 build.py --only x                         # собрать одну страницу (content/pages/x.json), остальное не трогать;
                                                  #   у жанровой — вместе со страницами её альбомов
python3 build.py --check content/albums.json      # проверить альбомы (id, жанры, дубли, файлы) и собрать их страницы в памяти
python3 build.py --strict                         # полная сборка; при любой ошибке site/ не трогается
```

Полная сборка пишет: все страницы, страницы альбомов (`site/<жанр>/<альбом>/index.html`), `404.html`, `sitemap.xml`, `robots.txt`, страницу-редирект `comments/index.html`
(старый адрес отзывов → `/otzyvy/`), готовые правила 301 `.htaccess` (Apache) и `_redirects` (Netlify, Cloudflare Pages), копирует ассеты. В конце проверяет, что каждая ссылка и каждый файл в `site/`
разрешаются относительно страницы, и перечисляет страницы из карты сайта, которые ещё не написаны.

Сборка печатает для каждой страницы объём текста: всего и «на виду» (без раскрываемого `seo-text` и свёрнутых ответов FAQ),
и предупреждает, если на главной текста на виду больше ~1600 знаков или где-то проскочило «Саша».

Посмотреть локально: двойной клик по `site/index.html` или `python3 -m http.server 8080 --bind 127.0.0.1 --directory site` → http://127.0.0.1:8080/.

## Как устроены ссылки

Все внутренние ссылки и пути к ассетам в `site/` — **относительные, с явным `index.html`**:
со страницы `/svadby/` на главную — `../index.html`, на отзывы — `../otzyvy/index.html`, стили — `../assets/css/main.css`.
Поэтому сайт работает и с диска (file://), и из любой папки на хостинге. К CSS и JS добавляется `?v=хэш` — после
пересборки браузеры не держат старую версию.

Canonical, og:url, sitemap и JSON-LD — абсолютные чистые адреса от `site_url` (`https://anphotolab.ru/svadby/`).

В контенте ссылки пишутся чистыми адресами (`/svadby/`) — относительными их делает генератор.

## Как добавить…

**Страницу.** Скопируйте ближайший эталон (`korporativy.json` — жанр, `fotograf-na-konferentsiyu.json` — SEO-страница),
назовите файл по slug без слэшей (`/fotograf-v-klub/` → `fotograf-v-klub.json`), замените тексты и кадры по `content/BLOCKS.md`,
проверьте `--check`, соберите. Если адреса нет в `src/config.json → pages`, добавьте его туда — иначе страница не появится
в меню и подвале (генератор предупредит).

**Фото.** Добавьте строку в `content/photos.json → photos`: новый `id` (следующий по счёту; на сайте номер не показывается),
`genre` (ключ жанра), `orientation` (`landscape`/`portrait`/`wide`), `w`/`h` среднего размера (1280×853, 1280×1920, 1280×720),
`alt` (что в кадре + жанр, по-русски, без спама ключами) и три URL: `thumb` (480 px по ширине), `mid` (1280), `large` (1920).
На жанровых страницах кадры показываются альбомами — новый кадр впишите в альбом в `content/albums.json` (или соберите
реальный альбом из папки, см. ниже); в галереях SEO-страниц со списком `ids` его нужно вписать.
Число кадров жанра показывается только на обложке жанра и только если кадров 6 и больше (`MIN_COUNT_SHOWN` в `build.py`):
«1 кадр» у свадеб или авто работал бы против доверия. Во вкладках и меню ни счётчиков, ни номеров (v3) — только названия.

**Отзыв.** Добавьте запись в `content/reviews.json` со следующим `id` — дословно. Страница `/otzyvy/` с `"layout": "wall"`
покажет его автоматически; на других страницах отзывы выбираются по `id`.

**Жанр** (редко). Запись в `src/config.json → genres` (ключ, slug, название, «единственное число» для кейсов и крошек, `cat` — подпись-категория (v3 в списке направлений не выводится), описание),
адрес в `pages`, обложка в `content/photos.json → covers`.

## Альбомы: как добавить реальную съёмку

На странице жанра — сетка альбомов («окна» съёмок), у каждого альбома своя страница `/<жанр>/<альбом>/` с крошками,
всеми кадрами в лайтбоксе, «Следующий альбом →» и CTA Telegram. Данные — `content/albums.json`, формат и проверки —
`content/BLOCKS.md` → § 4a. Сейчас там 19 **демо-альбомов** (`"demo": true`) из кадров `photos.json` с нейтральными
названиями — их список в `content/TODO-facts.md`; по мере появления реальных съёмок демо убираются.

**Добавить съёмку из папки с фото** (например, «Иван и Анна» прислали в `~/Desktop/ivan-anna`):

```bash
python3 tools/add_album.py --genre svadby --title "Иван и Анна" --folder ~/Desktop/ivan-anna \
    --subtitle "Загородный клуб · сборы, регистрация, прогулка" --year 2025 --cover 3
python3 build.py --check content/albums.json
python3 build.py
```

* Берутся все JPG/JPEG/PNG из папки по порядку имён (`IMG_2` раньше `IMG_10`). Оригиналы не трогаются.
* В `src/assets/img/albums/svadby/ivan-i-anna/` появятся `01.jpg`, `02.jpg`… — до 2400 px по длинной стороне (меньшие не
  увеличиваются), JPEG, метаданные (GPS, камера) не копируются — и превью `01-800.jpg`… (800 px).
  Обработка — Pillow (`pip install pillow`, поворот по EXIF учитывается), если нет — системная утилита macOS `sips`
  (она поворот по EXIF не применяет: кадры «с телефона на боку» лучше готовить с Pillow).
* В `content/albums.json` дописывается альбом (`"demo": false`): slug — транслит названия (`ivan-i-anna`), обложка —
  `--cover N` (N-й кадр по порядку, по умолчанию первый), у кадров — `src`, `thumb`, размеры и `alt` вида
  «Иван и Анна — свадьба, кадр 3». **Поправьте `alt` по смыслу** (что в кадре) — это текст для поиска и скринридеров.
* Новый альбом встаёт первым среди альбомов жанра (после других реальных) — перед демо. Убрать демо жанра сразу:
  `--drop-demo`. Заменить альбом с тем же названием: `--replace`. Свой адрес: `--slug ivan-anna-2025`. Текст: `--text "…"`.
* Убрать альбом (запись и файлы): `python3 tools/add_album.py --genre svadby --remove ivan-i-anna`.

**Вручную** — тоже можно: в `content/albums.json` кадр альбома — это id из `photos.json` (`73`) или объект
`{"src": "assets/img/albums/<жанр>/<slug>/01.jpg", "w": 2400, "h": 1600, "alt": "…"}` (файл кладёте в `src/assets/img/albums/…`).
Порядок альбомов в файле = порядок карточек на странице жанра. Проверка — `python3 build.py --check content/albums.json`.

**Вес.** Кадр 2400 px в JPEG — примерно 0,4–1 МБ; на странице альбома браузер берёт превью 800 px или полный кадр по `srcset`,
лайтбокс — полный. Съёмку на 150 кадров лучше сократить до 30–60 лучших: альбом на сайте — витрина, не выдача заказчику.

## Деплой

Подходит любой статический хостинг: залейте **содержимое** папки `site/` в корень сайта.

* **Обычный хостинг / S3 / Yandex Object Storage / Selectel:** загрузить файлы `site/`, индексный документ — `index.html`,
  документ ошибки — `404.html`.
* **Netlify / Vercel / Cloudflare Pages / GitHub Pages:** папка публикации — `site`, команда сборки — `python3 build.py`
  (или не указывать и заливать готовую `site/`).
* На сервере стоит настроить: HTTPS, 301 с `www` и `http` на основной адрес. 301 с `/comments/` на `/otzyvy/` уже есть в
  `site/.htaccess` (Apache) и `site/_redirects` (Netlify, Cloudflare Pages); на Netlify, чтобы правило перекрыло файл-заглушку,
  поставьте `301!`. Для nginx: `location ~ ^/comments(/|/index\.html)?$ { return 301 /otzyvy/; }`.
  Запасной вариант без настройки — `site/comments/index.html`: meta refresh + JS + canonical (без noindex — вместе с canonical это противоречивый сигнал).

## Фото с CDN wfolio (hotlink) и как перенести их к себе

**Быстрый шаг для скорости первого экрана (LCP).** Портрет на главной и обложки жанров лучше отдавать локально в AVIF/WebP:
положите оригиналы в `content/photos-src/` с именем по id (`093.jpg`, `037.jpg`, …) и выполните
`python3 tools/photos.py` → в `src/assets/img/photos/` появятся `093-640.avif`, `093-1280.webp` и т. д., а `python3 build.py`
сам поставит `<picture>` (AVIF → WebP → JPEG с CDN) и preload на AVIF. Без оригиналов можно `python3 tools/photos.py --from-cdn`
(скачает вариант `large` с CDN — качество хуже оригинала). Удалили файлы — вернётся JPEG с CDN, ничего не ломается.

Сейчас все кадры подключены напрямую с `i.wfolio.ru` — CDN старого сайта. Для запуска это допустимо, но есть риски:
если тариф wfolio отключится или сменятся токены в адресах, **все фото на сайте пропадут**; CDN может начать блокировать
чужой Referer; картинки индексируются под чужим доменом; нет контроля над форматами (WebP/AVIF) и кэшем.

Как перенести:
1. Попросить у Александра оригиналы (не скачивать с CDN — там уже пережатые копии).
2. Сделать три размера каждого кадра — 480, 1280 и 1920 px по ширине, лучше в WebP (и JPEG как запасной),
   имена транслитом: `korporativ-novosibirsk-037-1280.webp`.
3. Положить их на свой хостинг или в объектное хранилище с CDN.
4. Заменить URL в `content/photos.json` (`thumb`, `mid`, `large`) — это единственное место, где они записаны,
   и пересобрать сайт. Если фото будут лежать внутри `site/`, кладите их в `src/assets/img/photos/` и пишите пути
   от корня (`/assets/img/photos/...`) — генератор сделает их относительными. Заодно уберите
   `<link rel="preconnect" href="https://i.wfolio.ru">` (в `build.py`, функция `head`).

## Дизайн-система v2 «Проявочная»

Темнота фотолаборатории, кремовый свет текста и единственный цвет — красно-оранжевый градиент лабораторной лампы (safelight).
Референсы: antongutorov.com (имя на всю ширину + плашки-метки, моно-подписи, инверсные плашки), iampolie.ru (почти чёрный фон,
кремовый текст, навигация в скобках, список направлений крупными словами), axishome.ru (градиент #000 → #9B0000 → #FF6200 →
#9B0000 → #000, свечение, огромные узкие буквы).

**Редакция v3 «аккуратнее»** (отзыв заказчика: «очень много всего-всего… минимализм и аккуратность, стиль такой же»).

## Загрузка и переходы

Сайт открывается «как в проявочной»: в темноте загорается лампа, и страница проявляется в её красном свете.
Три режима, все — только с JS и без библиотек (двигаются только `transform`, `opacity`, `scale`):

| Режим | Когда | Что происходит | Длительность |
|---|---|---|---|
| **Лоадер** (`ld-on`) | первый визит за сессию (вкладку) | лампа-точка загорается с мерцанием, вокруг растёт и «дышит» safelight-свечение, по углам моно-метки (ANPhotoLab, имя, Photo & Video Lab, город, «Проявка…»), огромный счётчик 000 → 100 «проявляется» снизу вверх кремовым с красно-оранжевым краем, под ним — тонкая линия прогресса. На 100: цифры уходят вверх из маски, тёмный лист поднимается, под его нижним краем — полоса засветки, и ровно в этот момент стартует появление первого экрана (буквы имени, портрет, плашки) | счётчик ≈ 1,45 с, выход 0,9 с; потолок — 2,8 с от начала загрузки |
| **Появление** (`veil-in`) | повторная загрузка / переход на другую страницу в той же сессии, а также 404 | лист закрыт с первого кадра (горит только лампа) и уходит вверх, открывая страницу | ожидание шрифтов ≤ 0,3 с + 0,5 с |
| **Уход** (`veil-out`) | клик по ссылке на другую страницу сайта | лист накрывает экран снизу вверх (верхний край светится), затем переход | 0,34 с |

**Как устроено.**
* Разметка — `<div class="veil" id="veil" aria-hidden="true">` первым элементом `<body>` на всех страницах (генератор, `PageCtx.curtain`);
  на 404 — без счётчика (там человек и так расстроен: только короткое появление; визит не отмечается, поэтому с 404 на главную — полный лоадер).
  Страница-редирект `comments/` — без шторки. Ссылок и кнопок внутри нет, фокус лоадер не забирает.
* Какой режим включить, решает inline-скрипт в `<head>` (`boot_script` в `build.py`) **до первой отрисовки** — поэтому контент
  не мелькает перед лоадером. Он читает флаг `anp-seen` из `sessionStorage` (если хранилище недоступно — file://, приватный режим —
  запасной флаг в `window.name`, иначе визит считается первым) и ставит на `<html>` класс `ld-on` или `veil-in`.
* Стили — `main.css`, § 24 «Загрузка и переходы» (всё под `.js`: без JS шторки нет вовсе). Логика — `main.js`, модуль «Загрузка и переходы».
* Готовность для лоадера = DOM + `document.fonts.ready` + `img.decode()` кадра первого экрана (`fetchpriority="high"`). `window.load` не ждём:
  счётчик идёт по времени и догоняет до 100, когда всё готово; пока не готово — замедляется у 90. Если CDN с фото тормозит,
  выход всё равно начнётся не позже 2,8 с от начала загрузки. Цифры счётчика появляются, только когда загрузился их шрифт (≤ 0,7 с).
* Прокрутка заблокирована, только пока лоадер на экране (`scrollbar-gutter: stable` — ширина страницы не прыгает).
  Появления блоков при скролле и счётчики цифр стартуют после ухода шторки, а не под ней.
* Не перехватываются: `target="_blank"` (Telegram, WhatsApp), `tel:`/`mailto:`, другие сайты, якоря на этой же странице,
  клики с Ctrl/Cmd/Shift/Alt и средней кнопкой, `download`, ссылки на картинки и файлы, лайтбокс, ссылки внутри `<dialog>`,
  клики, которые уже обработал другой скрипт, и всё с атрибутом `data-no-pt` (на ссылке или её родителе).
  Ссылка из открытого меню: меню не закрывается, его накрывает шторка.
* Кнопка «Назад» (bfcache): страница вернулась с закрытой шторкой — она сразу открывается (и меню, если было открыто, закрывается).
* `prefers-reduced-motion: reduce` — ни лоадера, ни шторок, страница сразу на месте.
* Страховки от «вечного» оверлея: `main.js` не загрузился за 2,5 с — шторка снимается и страница показывается без анимаций;
  inline-таймер снимает шторку через 4,5 с; у `main.js` свой таймер (от момента, когда вкладка стала видимой — если сайт открыли
  в фоновой вкладке, лоадер покажется при переключении на неё); переход не случился за 6 с — шторка уходит.

**Где менять.**
* Длительности — объект `PT` в начале модуля «Загрузка и переходы» в `src/assets/js/main.js`:
  `count` (счётчик, мс), `hold` (пауза на «100»), `exit` (уход листа после лоадера), `ceil` (потолок лоадера от начала загрузки),
  `reveal` (появление), `cover` (накрытие при уходе). Если меняете `cover`, поменяйте и `transition` у `.veil-out .veil__sheet` в `main.css` (сейчас `.34s`).
* Высота засветки у края листа — `--vb` у `.js .veil`; её цвета — `.veil__sheet::before/::after`; свечение лампы — `.ld-on .veil__glow`;
  размер счётчика — `.ld__n`; тексты меток — `PageCtx.curtain` в `build.py`.

**Как отключить.** В начале `build.py`: `LOADER = False` — без счётчика, при первом визите сразу короткое появление;
`TRANSITIONS = False` — ни лоадера, ни шторок (разметки и классов нет, всё как раньше). Затем `python3 build.py`.
Отдельную ссылку — атрибутом `data-no-pt`.
