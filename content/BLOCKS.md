# Библиотека блоков ANPhotoLab v2 «Проявочная»

Страница сайта — это один JSON-файл в `content/pages/`. Генератор `build.py` превращает его в `site/<slug>/index.html`:
раскладывает блоки, ставит типографику, считает ссылки, пишет SEO-разметку. HTML руками не пишем.

**Главное правило v2: фотографа оценивают глазами.** На виду — кадры и огромная типографика, текста мало.
Полный SEO-текст живёт в раскрываемом блоке `seo-text` («Подробнее о съёмке»): он есть в HTML для поисковиков,
но не загромождает страницу.

**Правило v3 (бриф `_work/brief-v3.md`): «тот же стиль, только аккуратнее».** Каждый элемент на экране должен работать.
Генератор сам выводит спокойную версию: шапки секций — простая моно-метка без рамки и заголовок одного веса (800),
без правых мета-подписей; на плитках галерей нет подписей «№ …» (подпись — в лайтбоксе); направления — сдержанный
список слов (наведение — лёгкое увеличение); цифры без «+»-перекрестий; кейсы — сетка карточек; нумерации 01–07
во вкладках, меню, вопросах и «Как снимаю» нет. Поля JSON, которые больше не выводятся (`meta` у секций, `eyebrow`/`meta`
у `lead-form`, `previews` у `directions`), генератор принимает молча — страницы не ломаются.
**Портфолио v3 — альбомами** (бриф v3 §3): на жанровой странице вместо общей стены кадров — сетка альбомов съёмок («Иван и Анна»,
«Алёна и Дима»…), у каждого альбома своя страница `/<жанр>/<альбом>/`. Данные — `content/albums.json` (§ 4a), блок — `albums` (§ 6.6a).

Эталоны:

| Что пишете | Эталон | Коротко |
|---|---|---|
| Главная | `home.json` | портрет + огромное имя → направления → избранные кадры → цифры → кейсы → вопросы → заявка (Telegram) |
| Жанр | `korporativy.json` | огромное слово жанра + обложка → вкладки → альбомы съёмок (`albums`) → как снимаю → вопросы → подробнее → заявка |
| Альбом | — (JSON-страницы нет) | генератор сам собирает `/<жанр>/<альбом>/` из `content/albums.json`: крошки, название, кадры, «Следующий альбом →», заявка |
| SEO-страница (услуга) | `fotograf-na-konferentsiyu.json` | без вкладок: подборка кадров → как снимаю → вопросы → подробнее → другие направления → заявка |
| Контакты | `contacts.json` | `contact-hero` (портрет + Telegram крупно) → что написать → вопросы → подробнее |

Заглушки (цифры опыта, кейсы, демо-альбомы) перечислены в `content/TODO-facts.md` — добавляете новую, пишите туда строку.

## 1. Как работать

```bash
python3 build.py --check content/pages/portrety.json   # проверить страницу, ничего не записывая
python3 build.py --only portrety                       # собрать только её → site/portrety/index.html (+ страницы её альбомов)
python3 build.py --check content/albums.json           # проверить альбомы: id, жанры, дубли, файлы, обложки
python3 build.py                                       # собрать весь сайт (site/ пересобирается целиком)
```

`--check` печатает ошибки (страница не соберётся), предупреждения (соберётся, но стоит поправить) и **объём текста**:
«полезного текста N знаков, из них на виду M». «На виду» — без раскрываемого `seo-text` и без свёрнутых ответов FAQ.

| Страница | Всего (с seo-text) | На виду |
|---|---|---|
| Главная | — | до ~1500 (генератор предупредит, если больше 1600) |
| Жанр | 2500–4000 | 1200–2000 |
| SEO-страница | 3000–5000 | 1200–2000 |

Предупреждение «страницы ещё не написаны, ссылки заработают после их появления» — нормально, пока другие страницы в работе.

Смотреть результат: http://127.0.0.1:8080/<slug>/ или двойной клик по `site/<slug>/index.html`.

## 2. Файл страницы

**Имя файла = slug без слэшей.** Главная — `home.json`, `/korporativy/` → `korporativy.json`.
Файлы, начинающиеся с `_`, генератор пропускает (черновики).

```json
{
  "slug": "/portrety/",
  "type": "genre",
  "genre": "portrety",
  "nav": "Портреты",
  "title": "Портретная фотосессия в Новосибирске",
  "description": "…110–170 знаков…",
  "h1": "Портретная фотосессия в Новосибирске",
  "og_image": 3,
  "service": "Портретная фотосъёмка",
  "blocks": [ … ]
}
```

| Поле | | Что это |
|---|---|---|
| `slug` | обязательно | Адрес со слэшами. Совпадает с именем файла. Список адресов — `src/config.json → pages`. |
| `type` | обязательно | `home` · `genre` · `seo` · `service` (услуги, отзывы, обо мне, контакты). От типа зависят крошки и JSON-LD. |
| `title` | обязательно | SEO-фраза для `<title>` и og:title. Хвост « — Александр Непомнящих» генератор добавляет сам (единый шаблон); если с ним выходит больше 70 знаков (в выдаче хвост обрежется) — ставит короткий « — ANPhotoLab». Ключ в начале. У главной — как написано. |
| `description` | обязательно | meta description, 110–170 знаков. |
| `h1` | обязательно | Единственный H1. Выводит его первый экран (`hero-person` или `genre-hero`). |
| `blocks` | обязательно | Блоки сверху вниз. |
| `genre` | для `genre` | Ключ жанра: `svadby reportazh portrety avtomobili vypusknye kontserty korporativy`. Даёт активную вкладку, число кадров на обложке (только если кадров ≥ 6). |
| `nav` | желательно | Короткая подпись: крошки, списки направлений, меню. |
| `og_image` | желательно | id кадра для соцсетей и JSON-LD. |
| `service` | для `genre`/`seo` | `serviceType` в разметке Service. |
| `parent` | нет | Средняя ступень крошек. У `seo` по умолчанию `"/uslugi/"`. |
| `noindex` | нет | `true` — не индексировать, не класть в sitemap. |
| `breadcrumbs` | нет | `false` — скрыть крошки. |
| `schema` | нет | Дополнительно `["Service"]` или `["ImageGallery"]`. FAQPage, BreadcrumbList, ProfessionalService, Person, WebSite, WebPage ставятся сами. |
| `_comment` | нет | Заметка для людей. |

**В каждой странице:** ровно один первый экран (`hero-person` или `genre-hero`) и, почти всегда, одна `lead-form`
в конце. **Форм на сайте нет.** Кнопки «Обсудить съёмку» в шапке, меню, подвале и все CTA страницы с `"href": "#zayavka"`
генератор превращает в ссылку на Telegram (`config.json → contacts.telegram`, сейчас https://t.me/hoonigan866) —
в новой вкладке, с меткой `data-cta="tg"` для аналитики. Ник меняется в одном месте: `contacts.telegram` и `contacts.telegram_handle`.

## 3. Текст: markdown-lite, типографика, голос

* Абзацы — **массив строк**: `"paragraphs": ["Первый.", "Второй."]`. Список внутри — вложенный массив. Подзаголовок H3 — строка с `### `.
* `**жирный**` — ключевая фраза (1–2 раза на блок).
* `*акцент*` — **инверсная плашка** в тексте (кремовый фон, тёмные буквы — приём Гуторова). **В заголовках v3 акцент
  ничего не меняет** — заголовки одного веса (800), приём «жирное + тонкое» убран. Звёздочки в старых заголовках
  (`"Частые *вопросы*"`) можно не удалять, но в новых не пишите. Антиквы нет — только гротески.
* `[текст](/slug/)` — внутренняя ссылка; можно `(/slug/#voprosy)`, `(#zayavka)`, `(tel:…)`, `(https://…)`.
  Пишите **чистые адреса** — генератор сам сделает относительные ссылки с `index.html` (сайт работает с file://).
* Типографику руками не ставим: неразрывные пробелы после коротких слов и перед тире, «ёлочки», № и число — всё сам.
* HTML внутри JSON не работает.

**Голос.** Первое лицо **Александра** (не «Саша» — на сайте только «Александр»; цитаты отзывов остаются дословными).
Спокойно и конкретно. Без «запечатлею яркие моменты», «профессиональный подход». **Факты — только из `_work/brief.md`.**
Нельзя: цены, стаж, бренды клиентов, техника, награды, публикации, выдуманная биография. Цифры-заглушки и кейсы —
только с записью в `content/TODO-facts.md`. Новосибирск упоминаем явно.

## 4. Фото

Манифест — `content/photos.json`: у кадра `id`, `genre`, `orientation` (`landscape` 3:2, `portrait` 2:3, `wide` 16:9), `alt`, три размера.
`covers` — обложки жанров, `author` — портрет Александра (id 93, первый экран главной).

Кадров по жанрам: portrety 26, korporativy 22, vypusknye 19, reportazh 14, kontserty 9, svadby 1, avtomobili 1.

* На жанре — **все кадры своего жанра** (разложены по альбомам, § 4a). На SEO-странице — только из жанров, разрешённых планом (`photoGenres`).
* **Свадьбы и авто — по одному кадру.** Чужие не ставим: `genre-hero` с `"variant": "solo"`, ниже — один демо-альбом из этого
  кадра (страница альбома показывает его крупно и целиком). Реальные съёмки — `tools/add_album.py` (§ 4a).
* На жанровых страницах кадры живут **в альбомах** (§ 4a), на SEO-страницах и главной — в галерее `gallery`.
* `"focus": "50% 30%"` — какая точка кадра остаётся в центре при кадрировании (как object-position).
* Фото цветные, без фильтров. При появлении кадры «проявляются» (из красного полумрака в цвет) — это делает CSS.

## 4a. Альбомы съёмок — `content/albums.json`

Портфолио жанра — это **альбомы съёмок** («окна»): «Иван и Анна», «Алёна и Дима», «Выпускной 11 класса»… На странице жанра —
сетка карточек (блок `albums`, § 6.6a), у каждого альбома своя страница `/<жанр>/<slug>/`. Реальных альбомов пока нет: в файле
19 **демо-альбомов** (`"demo": true`) — кадры из `photos.json`, сгруппированные по похожим съёмкам, с нейтральными названиями.
Все они перечислены в `content/TODO-facts.md` — заменить реальными.

```json
{
  "_comment": "…",
  "albums": [
    {"genre": "reportazh", "slug": "delovoy-priyom", "title": "Деловой приём", "subtitle": "Зал с золотой отделкой · гости и общение",
     "year": null, "cover": 73, "photos": [73, 67, 86], "text": "", "demo": true},
    {"genre": "svadby", "slug": "ivan-i-anna", "title": "Иван и Анна", "subtitle": "Загородный клуб · сборы, регистрация, прогулка",
     "year": 2025, "cover": "assets/img/albums/svadby/ivan-i-anna/02.jpg", "text": "", "demo": false, "photos": [
      {"src": "assets/img/albums/svadby/ivan-i-anna/01.jpg", "thumb": "assets/img/albums/svadby/ivan-i-anna/01-800.jpg", "w": 2400, "h": 1600, "alt": "Жених и невеста на крыльце загородного клуба"},
      {"src": "assets/img/albums/svadby/ivan-i-anna/02.jpg", "w": 1600, "h": 2400, "alt": "Невеста у окна во время сборов"}
    ]}
  ]
}
```

| Поле | |
|---|---|
| `genre` | ключ жанра (`svadby`, `reportazh`, `portrety`, `avtomobili`, `vypusknye`, `kontserty`, `korporativy`). Обязательно. |
| `slug` | адрес альбома внутри жанра: латиница, цифры, дефис (`ivan-i-anna` → `/svadby/ivan-i-anna/`). Внутри жанра не повторяется. Обязательно. |
| `title` | название — H1 страницы альбома и заголовок карточки. Обязательно. |
| `subtitle` | строка под названием («Загородный клуб · сборы, регистрация, прогулка») — на странице альбома и в description. |
| `year` | год съёмки или `null`. Есть — попадает в мету: «Свадьба · 2025 · 48 кадров». |
| `cover` | обложка карточки и `og:image`: **id кадра** (число) или **`src` локального кадра** этого альбома. Нет — первый кадр. |
| `photos` | кадры по порядку (см. ниже). Пустой альбом — ошибка. |
| `text` | 1–2 строки о съёмке (строка или массив абзацев, markdown-lite). Необязательно. |
| `description` | свой meta description (110–170 знаков). Нет — генератор соберёт из названия, подзаголовка, жанра и числа кадров. |
| `demo` | `true` — демо-альбом (заглушка). Реальные — `false`. |

**Кадр альбома** — одно из двух:
* **id из `content/photos.json`** (число, как в галереях): `73`. Можно `{"id": 73, "focus": "50% 30%"}`. Кадр должен быть того же жанра, что альбом.
* **Локальный файл** — объект `{"src": "assets/img/albums/<жанр>/<slug>/01.jpg", "w": 2400, "h": 1600, "alt": "…"}`.
  `src` — путь внутри `src/` (без слэша в начале; файл копируется в `site/` вместе с остальными ассетами), `w`/`h` — размер
  файла в пикселях, `alt` — что в кадре (обязательно по смыслу; пустой — предупреждение и подпись «<Альбом>, кадр N»).
  Необязательно: `thumb` — превью (по умолчанию генератор ищет рядом `01-800.jpg`), `focus`. Форматы: JPG, PNG, WebP, AVIF.
  Такие альбомы делает `tools/add_album.py` (README → «Альбомы: как добавить реальную съёмку»): уменьшает фото до 2400 px
  по длинной стороне, делает превью 800 px и пишет запись сам.

**Проверки** (`python3 build.py --check content/albums.json` и при каждой сборке, отчёт «content/albums.json»): нет такого жанра,
плохой или повторяющийся slug, нет кадра с таким id, **кадр чужого жанра**, **кадр повторяется в альбоме**, **пустой альбом**,
нет файла `src`, нет `w`/`h`, обложка не из этого альбома — ошибки: такой альбом не выводится ни в сетке, ни отдельной
страницей. Кадр сразу в двух альбомах, неизвестное поле, пустой `alt` — предупреждения. В сводке — сколько альбомов по жанрам,
сколько демо и какие кадры жанра не попали ни в один альбом (не ошибка: например, дубль серии № 007 убран намеренно).

**Страница альбома** `/<жанр>/<slug>/` — JSON-страницы у неё нет, генератор собирает её сам (`AlbumCtx` в `build.py`):
* первый экран (v3 «аккуратнее»): крошки «Главная / Свадьбы / Иван и Анна» сверху, ниже одной колонкой слева — мета
  «Свадьба · 2025 · 48 кадров», название крупно, подзаголовок строкой под ним и текст; правый угол пустой;
* все кадры альбома — бенто с лайтбоксом (подпись в лайтбоксе — название альбома); **один кадр — крупно и целиком**
  (по высоте окна, без пустой сетки); первые кадры грузятся сразу, первый — с preload;
* «← Все съёмки жанра» (к сетке на странице жанра) и «Следующий альбом →» с миниатюрой — по кругу внутри жанра
  (у единственного альбома жанра — только «Все съёмки»);
* CTA-полоса Telegram — заголовок и строка берутся из `lead-form` страницы жанра («Обсудим свадьбу»).
* SEO: title «<Название> — <жанр> в Новосибирске — Александр Непомнящих» (≤ 70 знаков: длиннее — хвост « — ANPhotoLab»;
  если жанр уже в названии — «<Название>, Новосибирск — …»), description, canonical, `og:image` = обложка, JSON-LD
  CollectionPage + ImageGallery (все кадры, до 60) + BreadcrumbList; адрес — в `sitemap.xml` сразу после страницы жанра.
* Мета «N кадров» выводится от двух кадров (`ALBUM_MIN_COUNT_SHOWN` в `build.py`): «1 кадр» выдаёт тонкое портфолио.

## 5. Общие поля секций

| Поле | Что делает |
|---|---|
| `title` | Заголовок H2. Коротко: 1–3 слова (узкий гротеск капсом, один вес 800). v3: заголовки меньше, чем раньше, и не на всю ширину экрана: `xl` ≈ 6,2vw (до 108 px), `l` ≈ 4,6vw (до 80 px). |
| `title_style` | `xl` (крупный, по умолчанию) · `l` (поменьше) · `tag` (H2 в виде маленькой моно-метки — когда блок и так понятен: «Направления съёмки», «Кадры с корпоративов»). |
| `eyebrow` | Простая маленькая моно-метка над заголовком (без рамки и «лампы»). 1–2 слова, **чаще не нужна**: пишите, только если добавляет смысл («Принципы» над «Мои правила»). Генератор её не выводит, если заголовок совпадает с меткой, начинается с неё или уже содержит все её слова («Вопросы» над «Частые вопросы», «Кейс» над «Кейс»). |
| `meta` | **v3: не выводится** (константа `SECTION_META = False` в `build.py`) — правые мета-подписи «04 истории», «Нажмите — откроется крупно» убраны как шум. Поле можно оставить в JSON, генератор его молча пропустит; `True` в `build.py` вернёт подписи (в галерее `{n}` по-прежнему подставляет число кадров). |
| `note` | Строка под заголовком, до ~120 знаков. |
| `id` | Якорь (латиница). По умолчанию: `napravleniya`, `kadry`, `opyt`, `keysy`, `kak-snimayu`, `formaty`, `voprosy`, `podrobnee`, `drugie`… У `lead-form` всегда `zayavka`. |

Неизвестные поля генератор игнорирует с предупреждением. Блоки v1 (`page-hero`, `cta`, `genre-index`, `features`, `steps`,
`services`, `split`, `about`, `related`) удалены — генератор скажет, чем заменить.

## 6. Блоки

### 6.1 `hero-person` — первый экран главной: портрет + огромное имя

Портрет Александра на safelight-свечении, имя на всю ширину (на телефоне — две строки, каждая подогнана по ширине),
под ним кремовые плашки-метки. Имя + « — » + метки = H1 страницы (генератор сверяет).

```json
{"type": "hero-person", "photo": 93,
 "name": ["Александр", "Непомнящих"],
 "tags": ["фотограф", "и видеограф", "в Новосибирске"],
 "labels": ["Фотограф", "Видеограф", "Новосибирск"],
 "lead": "Снимаю там, где кипит жизнь — от дымных клубов до кабинетов с министрами.",
 "actions": [{"label": "Обсудить съёмку", "href": "#zayavka"}]}
```
v3: в первом экране только портрет в свечении, имя, плашки, одна строка и одна кнопка. Мета-строка сверху и строка
мессенджеров под кнопкой по умолчанию **не выводятся**.
| Поле | |
|---|---|
| `photo` | обязательно, id портрета (тёмный фон — он растворяется в свечении). Для скорости — локальный AVIF/WebP через `tools/photos.py` (README → «Фото»). |
| `name`, `tags` | слова имени и метки. В метке первое короткое слово («и», «в») показывается приглушённым. |
| `lead` | **одна** строка. |
| `actions` | кнопки `{label, href, style: "btn" | "ghost" | "link"}`. |
| `labels` | короткие слова на плашках («Фотограф · Видеограф · Новосибирск»); H1 для поиска — из `tags`. |
| `meta` | мета-строка над портретом — **только если задана** (v3 по умолчанию её нет; на телефоне скрыта всегда). |
| `messengers` | `true` — вернуть строку «Telegram: @… · WhatsApp» под кнопкой (v3 по умолчанию её нет; на телефоне скрыта всегда). |
| `focus` | точка кадрирования портрета. |

### 6.2 `genre-hero` — первый экран жанра, SEO и служебных страниц

Огромное слово на всю ширину (декоративное) + H1 = SEO-фраза подписью + лид + кнопки + обложка.
```json
{"type": "genre-hero", "word": "Корпоративы", "photo": 9, "focus": "50% 70%",
 "lead": "Ваша команда в лучшем свете: деловая часть, награждения, праздник."}
```
| Поле | |
|---|---|
| `word` | слово на всю ширину. По умолчанию — название жанра или `nav`. До ~12 букв. |
| `photo` | обложка; без неё — `variant: "text"`. |
| `variant` | `photo` (обложка 21:9, на телефоне 1:1) · `solo` (кадр на весь экран — для жанров с одним кадром) · `text`. |
| `lead` | 1–2 строки. |
| `facts` | **v3: не выводится** (константа `HERO_FACTS = False` в `build.py`) — строка «22 кадра · Новосибирск · Стоимость — по запросу» справа от крошек убрана как шум, в первом экране остаются только крошки. Поле можно оставить в JSON, генератор его молча пропустит. `True` вернёт строку: своё `facts` или по умолчанию «N съёмок» (число альбомов жанра, от двух; без альбомов — число кадров, от 6) и город. |
| `eyebrow` | пунктирная метка над словом (редко). |
| `actions` | по умолчанию «Обсудить съёмку» + «Смотреть съёмки ↓» (жанр с альбомами) или «Смотреть кадры ↓» (галерея). |
| `focus`, `focus_mobile`, `caption` | кадрирование и подпись обложки. Подпись на кадре — **только** `caption` (одна короткая строка: «ANPhotoLab · Новосибирск»); номер из архива и alt на обложке не выводятся. Без `caption` подписи нет. |

Слово подгоняется по ширине, но не выше 40 % высоты окна: короткое слово («Отзывы») не съедает первый экран, а встаёт влево своим размером.
Вертикальная обложка (`orientation: portrait`, например портрет автора на «Обо мне») не режется в полосу 21:9 — кадр 4:5 встаёт рядом с H1 и текстом.
Обложку, которой нет в галерее, лайтбокс открывает первой, дальше стрелками — кадры галереи страницы.

### 6.2a `contact-hero` — первый экран «Контактов» (портрет + контакты)
Бриф v3 §4: портрет Александра крупно рядом с контактами. Десктоп: слева крупное слово («Контакты» — оно же начало H1,
остальная часть H1 — подписью), строка-лид, **Telegram главным** — ник крупно со стрелкой ↗ (ссылка в новой вкладке,
`data-cta="tg"`), ниже строка «Телефон · WhatsApp · Город»; справа — портрет 4:5. Телефон: крошки → слово → портрет
(квадрат, кадр по лицу) → лид → Telegram → контакты столбиком. Портрет «проявляется» так же, как обложка жанра.
```json
{"type": "contact-hero", "word": "Контакты", "photo": 93, "focus": "55% 34%", "focus_mobile": "56% 30%",
 "lead": "Расскажите о событии — отвечу и рассчитаю стоимость. Быстрее всего — в Telegram."}
```
| Поле | |
|---|---|
| `word` | крупное слово. Если H1 страницы начинается с него — слово становится частью H1. По умолчанию — `nav`. |
| `photo` | портрет (id 93). Без него — одна колонка. `focus` / `focus_mobile` — кадрирование на десктопе (4:5) и телефоне (1:1). |
| `lead` | 1–2 строки. |
| `tg_label` | подпись над ником (по умолчанию «Telegram — быстрее всего»). Ник и ссылка — из `config.json → contacts`. |
| `items` | свои строки контактов `[{"label": "Телефон", "text": "+7 …", "href": "tel:…"}]`; по умолчанию — телефон, WhatsApp, город из `config.json`. |

Это первый экран (как `hero-person` / `genre-hero`): один на страницу, в нём H1, кадр — в preload. CTA-полоса `lead-form`
на «Контактах» не нужна — Telegram уже в первом экране.

### 6.3 `genre-tabs` — sticky-вкладки жанров
`{"type": "genre-tabs"}` — `[ Свадьбы ] [ Репортаж ] …` (v3: без номеров и счётчиков), активная — кремовая плашка,
прилипает под шапкой; на телефоне при скролле вниз шапка уезжает, вкладки встают на её место. Ставим сразу
после `genre-hero` на жанрах. Поля: `active` (slug), `label`.

### 6.4 `directions` — направления (сдержанный список слов)
v3 (бриф v3 §2, «наводишь на кнопку — она немного увеличивается и переводит на страницу»): столбик слов по центру,
кремовые с пониженной яркостью (.5), без плашки, всплывающих фото, подписей-категорий и номеров. Наведение и фокус
с клавиатуры — слово плавно увеличивается (scale 1.05, ~0,4 с) и становится полностью кремовым; клик — переход на
страницу жанра со шторкой. Ссылка шириной в слово. На телефоне и планшете — просто список (на касании — короткий отклик).
Такой же список — жанры в меню-оверлее. JS для блока не нужен.
```json
{"type": "directions", "id": "napravleniya", "title": "Направления съёмки"}
```
`items` — свой список slug-ов (по умолчанию все жанры) или `{slug, label}`. Шапка по умолчанию — метка (`tag`) по центру.
Поля `previews` и `cat` (и `config.json → genres[].cat`) больше не выводятся.

### 6.5 `related-directions` — «Другие направления» (тот же список, компактнее)
```json
{"type": "related-directions", "items": [
  {"slug": "/fotograf-na-konferentsiyu/", "label": "Конференции", "cat": "Деловые события"},
  "/reportazh/"]}
```
Элемент — slug или `{slug, label, cat, photo}`. По умолчанию (`layout: "list"`) — тот же сдержанный столбик слов, что у
`directions`, только мельче (без миниатюр и подписей). 4–6 пунктов.

`"layout": "grid"` — компактная сетка (на планшете 2 колонки, на телефоне — список) с миниатюрой, словом поменьше и стрелкой.
v3: подпись-категория `cat` над словом **не выводится** (шум, как у направлений); поле можно оставить. Колонки генератор выбирает
сам, чтобы последний ряд не висел одним пунктом: до 3 пунктов — в один ряд, 5–6 и 9 — по 3, 4, 7, 8 и 10 — по 4
(7 → 4 + 3); `columns` (2, 3 или 4) — вручную. Миниатюра —
обложка страницы, для ещё не написанной — обложка её жанра (`config.json → pages[].genre`), повторы и кадр первого экрана заменяются
другим кадром того же жанра; `photo` — свой id. Наведение — слово чуть увеличивается и светлеет, стрелка сдвигается (без заливки).
Для страниц, где списков несколько подряд (/uslugi/: «События», «Отдельные задачи»).

### 6.6 `gallery` — бенто-галерея с лайтбоксом
Кадры раскладываются по шаблонам рядов на 12 колонок сами: горизонтальные — крупный + два малых, три в ряд, пара;
вертикальные встают в вертикальные слоты (порядок внутри ряда может чуть поменяться). На телефоне — две колонки.
Клик — лайтбокс со стрелками, клавиатурой, свайпом, Esc.
```json
{"type": "gallery", "id": "raboty", "title": "Избранные кадры",
 "ids": [20, 62, 44, 75, 88, 16, 68, 47, 51],
 "end": {"text": "Полные подборки — на страницах направлений.", "link": {"label": "Всё портфолио", "href": "/uslugi/"}}}
```
| Поле | |
|---|---|
| `ids` | порядок кадров (число или `{"id": 5, "focus": "50% 30%"}`). |
| `genre` | все кадры жанра; вместе с `ids` — проверка полноты («в галерее нет кадров жанра…»). |
| `exclude`, `limit`, `min` | исключить, ограничить, скрыть блок при числе кадров меньше `min`. |
| `layout` | `bento` (по умолчанию) · `solo` (1–2 кадра крупно и целиком: по высоте окна, без обрезки). |
| `end` | строка и кнопка под галереей. |
| `group` | имя группы лайтбокса. |

**Кадры первого экрана и кейсов в галерее той же страницы не повторяются** — генератор убирает их сам (сообщение в `--check`),
в `ids` их можно не вычёркивать. Почти одинаковые кадры одной серии убирайте руками (`exclude`); один сюжет — не больше двух раз.
Подписи (v3): **на плитках подписей нет** — только кадр (номер кадра — шум). Подпись живёт в лайтбоксе (`data-cap`):
на главной и жанрах — название жанра кадра («Портреты»), на SEO и служебных страницах — название страницы. Alt живёт только в alt.
Наведение — кадр чуть приближается (1.03). Появление — плитка мягко проступает из темноты и из красного полумрака
переходит в цвет («проявка»).

Главная: **8–12 кадров**. Удачный ритм — чередовать «вертикальный, горизонтальный, вертикальный» и тройки горизонтальных.

### 6.6a `albums` — альбомы съёмок жанра (карточки-«окна»)
Сетка карточек альбомов жанра из `content/albums.json` (§ 4a): обложка в рамке, название, мета «Жанр · год · N кадров».
Без подписей и плашек на кадре; наведение/фокус — кадр чуть приближается внутри рамки (1.04); клик — страница альбома
(со шторкой перехода). При появлении обложки «проявляются», как кадры галереи.
```json
{"type": "albums", "title": "Съёмки"}
```
| Поле | |
|---|---|
| `genre` | чьи альбомы; по умолчанию — жанр страницы. |
| `items` | свой порядок / выбор: список slug альбомов (`["ivan-i-anna", "alyona-i-dima"]`). По умолчанию — все альбомы жанра в порядке файла. |
| `limit` | показать не больше N. |
| `columns` | 1, 2 или 3. По умолчанию: 1 альбом — широкая карточка (обложка + название, подзаголовок и «Смотреть съёмку →» рядом), 2 и 4 — две колонки, 3 и от 5 — три. Планшет — две, телефон — одна. Последний ряд трёх колонок без «дырок»: обложки 3:2 и 1:1 — хвост из двух карточек на половину ширины каждая (5 → 3 + 2, 7 → 3 + 2 + 2); портреты 4:5 — хвост того же размера по центру (5 → 3 + 2 по центру, 7 → 3 + 3 + 1 по центру), чтобы вертикальные обложки не вытягивались на весь экран. В двух колонках (планшет или `columns: 2`) нечётная последняя карточка — на всю строку, обложка и текст рядом. |
| `ratio` | пропорция обложек `3/2`, `4/5` или `1/1`. По умолчанию одна на сетку: 4:5, если вертикальных обложек больше, иначе 3:2. |

`title` по умолчанию «Съёмки», стиль заголовка — `l`. **Обложка карточки не повторяет кадр первого экрана страницы** — если
`cover` альбома стоит в `genre-hero`, на карточке берётся следующий кадр альбома (у альбома из одного кадра выбора нет).
Кнопка «Смотреть съёмки ↓» в первом экране жанра ведёт на этот блок (якорь `#syomki`). Альбомов у жанра нет — блок скрыт
(предупреждение). Альбомы с ошибками в `albums.json` не выводятся (предупреждение со списком).
В JSON-LD страницы жанра ImageGallery — обложки карточек.

### 6.7 `stats` — опыт в цифрах
Три крупных тонких (300) числа (v3: без «+»-перекрестий по углам) — над каждым тонкая линия, число и подпись по левому краю;
считаются от нуля один раз при появлении. Над числами — метка и 1–2 строки об Александре одной колонкой слева (v3: текст
сразу под меткой, без пустоты между ними). На телефоне три числа — в ряд, помельче.
```json
{"type": "stats", "title": "Опыт в цифрах", "text": "Event-фотограф и видеограф из Новосибирска…",
 "link": {"label": "Обо мне →", "href": "/about/"},
 "items": [{"value": 300, "suffix": "+", "label": "событий снято"},
           {"value": 7, "label": "направлений съёмки", "href": "#napravleniya"},
           {"value": 16, "label": "отзывов — дословно", "href": "/otzyvy/"}]}
```
3 пункта. `value` — число, `suffix` — «+», «ч» и т. п. **Каждая цифра-заглушка — в TODO-facts.md.**

### 6.8 `cases` — кейсы «Задача → Решение → Результат»
v3: простая аккуратная сетка карточек — 2 колонки на десктопе, 1 на телефоне; без стопки, затемнения, счётчиков «01 / 04»
и свёрнутых блоков. Карточка без фона: обложка 3:2 (клик — лайтбокс, подпись — название кейса), название, 2–3 метки
строкой через «·», три короткие строки Задача / Решение / Результат (результат — ярче), ссылка.
```json
{"type": "cases", "title": "Кейсы", "items": [
  {"photo": 1, "title": "Свадьба", "tags": ["8 часов съёмки", "≈ 600 кадров", "Готово за 14 дней"],
   "task": "…1 строка…", "solution": "…", "result": "…", "link": {"label": "Смотреть свадьбы →", "href": "/svadby/"}}]}
```
Сейчас — только на главной (2 или 4 карточки — ровная сетка). Тексты и метки — заглушки до данных заказчика
(обложки он тоже пришлёт) — см. `content/TODO-facts.md`. Метки — то, что важно заказчику жанра: длительность, объём, срок;
больше трёх — генератор предупредит. Каждая строка ≤ 120 знаков. Без названий компаний без их согласия.

### 6.9 `marquee` — бегущая строка отзывов

```json
{"type": "marquee", "ids": [5, 11, 7, 3, 15], "link": {"label": "Все 16 отзывов →", "href": "/otzyvy/"}}
```

### 6.13 `seo-text` — «Подробнее о съёмке» (раскрываемый)
Весь длинный текст для поисковиков: в HTML целиком, на экране — первые строки и кнопка «Читать полностью».
```json
{"type": "seo-text", "title": "Подробнее о съёмке корпоративов",
 "lead": "Первый абзац-тезис.",
 "paragraphs": ["Ключ в первом абзаце…", "### Что попадает в кадр", ["пункт", "пункт"], "…"]}
```
`sub` — подразделы `{title, paragraphs, list}`; `open: true` — раскрыт сразу. Сюда переносим тексты v1
(«что снимаю», «что получите», «как проходит»). Ссылки на смежные страницы — здесь же.

### 6.14 `text`, `quote`, `reviews` — для служебных страниц
* `text` — `lead`, `paragraphs`, `list`, `aside {title, text, items}`, `actions`. Для «Обо мне», «Контакты».
* `quote` — один отзыв крупно: `{"type": "quote", "review": 10, "eyebrow": "Отзыв о конференции"}` (или `text` + `author`).
  Отзывам жанр не приписываем, кроме Егора (№ 10 — конференция). **Одна цитата — одна страница** (дубли длинных отзывов между
  страницами — дублированный контент); длинный отзыв Константина (№ 9) — только на /otzyvy/. Подпись — имя автора (`cap` — по желанию),
  номер отзыва клиенту не показываем.
* `reviews` — стена отзывов: `{"type": "reviews", "title": "Отзывы"}` покажет все 16; `ids` — выбор, `all_link` — кнопка.

### 6.15 `lead-form` — CTA-полоса: заголовок + ссылка на Telegram на safelight

## 7. Рецепты

**Главная.** `hero-person` → `directions` → `gallery` (8–12) → `stats` → `cases` (2–4) → `faq` → `lead-form` (CTA — последний блок перед подвалом, как на жанрах).

```json
{"type": "lead-form", "title": "Обсудим свадьбу", "lead": "…"}
```
Кадр — на весь экран; ниже — один демо-альбом из того же кадра (широкая карточка), его страница показывает кадр крупно
и целиком. Чужие кадры не подставляем. Появятся реальные съёмки (`tools/add_album.py`) — встанут первыми, демо убрать `--drop-demo`.
